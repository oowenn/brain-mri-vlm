# Project progress tracking

- Read [IMPLEMENTATION.md](IMPLEMENTATION.md) before continuing project implementation or experiments. Use it to identify the current roadmap step, verified evidence, limitations, and next work.
- Keep `IMPLEMENTATION.md` current as part of meaningful project work and before handing the project back to the user. Update completed work, remaining tasks, verification results, decisions/blockers, evidence links, and the dated progress history.
- Keep its teammate setup section current when environment pins, cluster directories, cache variables, or launch commands change. Distinguish the verified reference installation from untested setup instructions and server-specific adaptations.
- Distinguish planned work, implemented but unverified code, running experiments, and verified completion. Follow the user's latest scope; do not treat a roadmap entry as proof that work has run.
- Preserve historical experiment evidence and reference exact commits, Slurm jobs, and W&B runs when available. Keep detailed file explanations in each step's README and summarize the current state in `IMPLEMENTATION.md`.
- Never put passwords, API keys, or temporary authentication details in project documentation or run evidence.
